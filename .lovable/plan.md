## Что делаем

На мобильной версии главной страницы (`/`) добавляем компактный пошаговый калькулятор-заявку **сразу после hero-блока, выше всех остальных секций**. На десктопе он остаётся скрытым (текущая большая форма внизу страницы сохраняется как есть).

## Как это будет выглядеть

Карточка с заголовком «Рассчитать выезд за 30 секунд» и 3 последовательно раскрывающимися шагами + финальный блок контактов:

```
┌─────────────────────────────┐
│  Рассчитать выезд           │
│                             │
│  ▸ Шаг 1. Город             │  ← открыт по умолчанию
│    [Краснодар]              │
│    [Сочи]                   │
│    [Ростов-на-Дону]         │
│    [Симферополь] ...        │
│                             │
│  ▸ Шаг 2. Тип объекта       │  ← раскроется после шага 1
│  ▸ Шаг 3. Проблема          │  ← раскроется после шага 2
│                             │
│  Телефон: [+7 ___ ___ __ __]│
│  ☐ Согласен с политикой     │
│  [ Оставить заявку ]        │
└─────────────────────────────┘
```

### Поведение шагов
- Каждый шаг — карточка-аккордеон с заголовком и галочкой выбранного значения справа.
- При выборе значения шаг автоматически сворачивается, и раскрывается следующий.
- Можно вернуться и нажать на любой пройденный шаг, чтобы изменить выбор.
- Контакты (телефон + согласие + кнопка) появляются только после прохождения всех 3 шагов (либо disabled до этого).

### Содержимое шагов
1. **Город** — список из `src/data/cities.ts` (8 городов), кнопки-пилюли в один столбик.
2. **Тип объекта** — Квартира / Частный дом / Офис-коммерция / Склад-производство / Другое.
3. **Проблема** — список из `src/data/services.ts` (8 услуг), используем `shortName`.

### Финальный блок
- Поле «Телефон» (обязательное, маска `+7`).
- Чекбокс «Согласен с обработкой персональных данных» со ссылкой на `/privacy`.
- Кнопка «Оставить заявку» (`bg-accent`), disabled пока: не пройдены шаги, не введён телефон, не отмечена галочка.
- При сабмите — `toast.success`, имитация отправки (как в `LeadForm`).

## Технические детали

### Новый компонент
`src/components/site/MobileQuickLead.tsx`:
- `useState` для: `city`, `objectType`, `problem`, `openStep` (0–2 или null), `phone`, `agree`, `loading`.
- Импорты: `cities` из `@/data/cities`, `services` из `@/data/services`, `Button`, `Input`, `Checkbox`, `Label`, `toast` из `sonner`, `Link` из `@tanstack/react-router`, иконки `Check`, `ChevronDown` из `lucide-react`.
- Внутренний саб-компонент `<StepCard>` с props `{ index, title, value, isOpen, onToggle, children }` — рендерит заголовок «Шаг N. …», справа выбранное значение или иконка `ChevronDown`, ниже список опций когда открыт.
- Список опций — `<button>` элементы с `rounded-xl border`, при выборе подсвечиваются `border-accent bg-accent/10` и появляется `Check`.
- Простая клиентская валидация (zod не нужен для UI-формы; такая же логика как в существующей `LeadForm`).

### Размещение
В `src/routes/index.tsx` сразу после закрывающего `</section>` hero-блока добавить:
```tsx
<section className="md:hidden border-b border-border bg-surface">
  <div className="container mx-auto px-4 py-6">
    <MobileQuickLead />
  </div>
</section>
```
Класс `md:hidden` гарантирует, что на десктопе компонент не отображается. Существующая секция с большой `<LeadForm />` внизу страницы остаётся без изменений.

### Стили
Используем только семантические токены (`bg-card`, `border-border`, `bg-accent`, `text-accent-foreground`, `bg-surface`, `text-muted-foreground`) — без хардкод-цветов.

### Что НЕ трогаем
- `LeadForm.tsx` — оставляем для десктопа и других страниц.
- Данные `cities.ts` / `services.ts` — только читаем.
- Десктопную верстку главной.
