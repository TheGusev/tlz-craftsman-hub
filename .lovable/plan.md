
## Цель

- **City×Service (72 страницы, 8 городов × 9 услуг)** — довести объём уникального текста до 800+ слов на страницу, усилить коммерческие и гео-сигналы (город в локативе, районы, климат/специфика, локальные примеры).
- **Блог (4 поста)** — довести каждый пост до 1200+ слов, выровнять по GEO-запросам (ЮФО, Крым, Краснодар, Ростов, Сочи, Симферополь и т.д.).

## Подход: city×service

Писать 72 текста руками нереалистично и приведёт к «водянистым» дублям. Использую **гибридный шаблон**: 6 новых параметризованных секций + слот для уникального ручного контента per-city (уже есть тип `ServiceInCity`, расширим).

### Новые секции на странице (в порядке сверху вниз)

1. **«Особенности {услуги} {в городе}»** — 2 абзаца, ~180 слов.
   Собирается из: климат города (`city.climate` — новое поле), типовые объекты города (`city.typicalObjects`), сезонные риски (`service.seasonalRisksByRegion`).
   Пример для «удаление плесени в Сочи»: субтропический климат, высокая влажность круглый год, частые ливни → плесень в подвалах гостиниц и в номерном фонде.

2. **«Что мы делаем {в городе}: 4 типовых сценария»** — 4 карточки по ~60 слов = ~240 слов.
   Собираются из `service.objects` × `city.typicalObjects` через таблицу шаблонов (5–7 паттернов на кластер услуг, ротация по хешу от `city.slug`, чтобы соседние города не совпадали).

3. **«Районы и логистика выезда {в городе}»** — ~120 слов.
   Расширяю блок «Районы выезда»: описание времени выезда по группам районов (`city.districtGroups` — новое поле: центр / спальники / пригород), пояснение «почему бригада успевает за X часов» (адрес базы из `city.address`).

4. **«Локальные примеры и материалы»** — ~150 слов.
   Параметризованный абзац: типичные материалы стен/полов в городе (панельки Ростова, частный сектор Краснодара, гостевые дома Ялты, сталинки Севастополя) × поведение конкретной услуги на них.
   Данные — в новом справочнике `src/data/cityBuildings.ts`.

5. **«Кому в {городе} чаще всего нужна {услуга}»** — ~120 слов.
   Сегменты аудитории (собственники, УК, отели, склады, рестораны) с примерами объектов и характерным поводом обращения. Формируется из `service.audienceSegments` × `city.economySectors` (новое поле).

6. **Existing `whenCalled`, FAQ, `caseScenario`** остаются как ручной override — если заполнены в `serviceInCity`, отображаются, иначе показывается шаблонная версия.

Итого автогенерация даёт ~800 слов уникального текста, при этом благодаря комбинации `(город, услуга, район, материал, сегмент)` пересечений между страницами минимум.

### Data changes (`src/data/cities.ts`)

Добавить в тип `City`:
- `climate: string` (одна фраза, например «Влажный субтропический климат, средняя влажность 75%»)
- `typicalObjects: string[]` (5–8 позиций: гостиницы, СНТ, частный сектор, панельки 70-х…)
- `economySectors: string[]` (4–6 позиций: туризм, порт, агро…)
- `districtGroups: { name: string; arrival: string; districts: string[] }[]` (2–3 группы)

### Data changes (`src/data/services.ts`)

Добавить в тип `Service`:
- `seasonalRisksByRegion: { yug: string; krym: string }` — 2 короткие фразы
- `audienceSegments: { title: string; description: string }[]` — 4 сегмента × ~40 слов

### Новый файл `src/data/cityBuildings.ts`

Мэппинг `citySlug → { walls, floors, note }` — типовой жилой/коммерческий фонд.

### Новый модуль `src/lib/cityServiceContent.ts`

Функции построения текстов секций 1–5 (детерминированно, без рандома в рантайме, чтобы SSR = CSR):
`buildFeatures(city, service)`, `buildScenarios(city, service)`, `buildLogistics(city)`, `buildBuildingContext(city, service)`, `buildAudience(city, service)`.

### Обновления `src/routes/cities.$citySlug.$serviceSlug.tsx`

Добавить 5 новых секций между `IntroAnswer` и «Этапы работ». Разметить `<h2>` + текст, без изменений схемы JSON-LD.

### Проверка объёма

Скрипт `scripts/count-words.ts` — прогнать по всем 72 URL, подтвердить ≥800 слов текстового контента (без меток/навигации).

## Подход: блог

Пишу вручную, каждый пост доводится до **~1200–1400 слов**. GEO-выравнивание: включить в тело упоминания ЮФО, Краснодарского края, Крыма, конкретных городов, где услуга применима, локальные примеры (панельки, гостевые дома Ялты и т.п.), сезонность.

### Пост 1. «Чем опасна плесень после затопления»
Секции: как развивается плесень; почему в ЮФО и Крыму риск выше (влажность, короткие зимы); материалы (штукатурка, гипсокартон, ОСП, ковролин); симптомы у людей; чек-лист первых 72 часов; когда нужен акт для страховой; локальные особенности (панельки Ростова, гостевые дома Сочи, подвалы Севастополя); мифы (уксус, хлорка); порядок работ; сроки и гарантии; FAQ (5 вопросов).

### Пост 2. «Что делать после пожара в квартире»
Секции: первые 24 часа; акт МЧС и что в нём указывать; страховая — какие фото и документы нужны; техника безопасности при уборке сажи (СИЗ, вентиляция); почему нельзя стирать текстиль дома; последовательность работ (сажа → запах → отделка); особенности регионов ЮФО (жара + сажа = запах закрепляется); частые ошибки; когда нужна экспертиза; отдельно про малогабаритки, сталинки, частный сектор; FAQ.

### Пост 3 и 4
Аналогично, каждый добирается до 1200+ слов, добавляются региональные примеры (Краснодар, Ростов-на-Дону, Симферополь, Ялта, Керчь), сезонность (лето/зима), ссылки на 2–3 услуги и 1 город.

### Правка данных

Только `src/data/blog.ts` — расширяются массивы `body[].paragraphs`, обновляются `readingMinutes` (12–14 мин), `metaDescription` не трогаем (уже валидные).

## Порядок работ

1. Расширить типы и данные в `src/data/cities.ts`, `src/data/services.ts`, создать `src/data/cityBuildings.ts`.
2. Написать `src/lib/cityServiceContent.ts`.

4. Подсчитать слова скриптом, при недоборе — расширить шаблоны.

6. Финальный подсчёт слов + `tsgo --noEmit`.

## Что НЕ входит

- Не трогаю canonical/robots/JSON-LD (уже поправлено в P0).
- Не переписываю услуги (`services.$serviceSlug`) — они уже длинные.
- Не пишу 72 полностью уникальных ручных текста — вместо этого генерирую параметризованно + оставляю слот для ручных вставок в `serviceInCity`.

## Оценка объёма

- **~72 city×service** — рост с ~350 до ~850 слов средних.
- **Блог**: 4 поста × ~1200 слов.
- Новый код: ~250 строк шаблонов + ~120 строк данных.
