## Главное: найдена причина, почему фото и видео не видно на сайте

Боевой сайт `sanitarnyeresheniya.ru` разворачивается по FTP на Beget (`.github/workflows/deploy.yml` → папка `dist/`). Фото потопа и видео залиты на CDN Lovable по путям `/__l5e/assets-v1/...` — эти пути существуют только на хостинге Lovable. Проверка:

- `https://tlz-craftsman-hub.lovable.app/__l5e/.../potop-video.mp4` → 200, video/mp4
- `https://sanitarnyeresheniya.ru/__l5e/.../potop-holl-lestnica.jpg` → **404**
- в собранной `dist/` папки `__l5e` нет

То есть на боевом домене все 4 фото потопа + видео + постер отдают 404 — битые картинки и пустой плеер. Это же касается обложки услуги «после потопа».

## Что делаем

### 1. Переносим медиа потопа в сборку (чиним 404)

- Кладём 4 фото потопа, постер и видео в `public/media/` — тогда они попадают в `dist/` и уезжают на Beget по FTP.
- Фото пережимаем в WebP (~200–300 КБ вместо 450–490 КБ), видео перекодируем ffmpeg (H.264, CRF ~28, ширина 720, faststart) — с 7 МБ примерно до 2–3 МБ.
- В `src/lib/floodGallery.ts` и `src/lib/serviceImages.ts` меняем ссылки с `.asset.json` на `/media/...`. CDN-пойнтеры удаляем через `lovable-assets delete`.

### 2. Ленивая загрузка видео

- В `BeforeAfterGallery.tsx` видео больше не грузится сразу: рендерим постер-картинку (`loading="lazy"`) с кнопкой «Смотреть видео»; `<video>` монтируется только по клику или когда блок попадает в зону видимости (IntersectionObserver, `rootMargin` ~200px).
- Убираем `autoPlay`, ставим `preload="none"`. Первая отрисовка не тянет мегабайты, LCP не страдает.
- В JSON-LD `VideoObject` ничего не меняем — разметка остаётся для поиска.

### 3. Новые фото по пожарам

Загружено 3 кадра: обгоревший шкаф (до), тот же шкаф после очистки/восстановления (после), уборка помещения после пожара. Что делаем:

- Кладём их в `public/media/` (WebP, сжатие).
- Новый модуль `src/lib/fireGallery.ts` по аналогии с `floodGallery.ts`: подписи «Шкаф после пожара: копоть и нагар» / «Тот же шкаф после очистки» / «Уборка помещения после пожара», alt со склонением города.
- Показываем через тот же `BeforeAfterGallery` (заголовок «Наши работы после пожара: до и после») на:
  - `/services/posle-pozhara`
  - `/cities/moskva/posle-pozhara`, `/cities/moskovskaya-oblast/posle-pozhara`
- В `serviceInlineImages.ts` для `posle-pozhara` отключаем общие стоковые кейсы, как уже сделано для потопа.

### 4. Проверка

- Прогон `build:prod` (134 маршрута, SEO-проверки) + проверка, что файлы реально лежат в `dist/media/`.
- Открываю страницы в браузере (Playwright), убеждаюсь: фото рендерятся, постер виден, видео стартует по клику, в консоли нет 404.

## Технические детали

- `public/media/` вместо `src/assets` — чтобы URL были стабильными и не зависели от хеширования Vite (удобно для постера в JSON-LD и `og`).
- Абсолютные URL в `VideoObject`/`thumbnailUrl` собираем через `SITE_URL`.
- Компонент видео выносим в `src/components/site/LazyVideo.tsx`, чтобы галерея осталась простой.
