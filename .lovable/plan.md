# Sitemap и robots: корректная индексация город×услуга и медиа

## Что не так сейчас

- В `sitemap.xml` 134 URL, из них 17 городов, ~60 страниц город×услуга и 12 кейсов относятся к скрытым южным регионам (Сочи, Краснодар, Крым, Ростов). Ссылок на них с сайта нет, но они отдают `index,follow` — Яндекс видит их как «страницы-сироты» и слабые дубли.
- `<lastmod>` для всех URL, кроме блога, подставляется как дата сборки. Это ложный сигнал: при каждом деплое все 134 страницы «обновляются», и поисковики перестают доверять полю.
- В sitemap нет медиа: реальные фото «до/после» (потоп, пожар) и видео нигде не заявлены для индексации в Картинках и Видео Яндекса/Google.
- `robots.txt` не содержит `Clean-param` для Яндекса, а вместо этого блокирует UTM-метки через `Disallow: /*?utm` — Яндекс такие правила понимает хуже и метки продолжают плодить дубли.

## Что сделаем

### 1. Индексируем только Москву и МО
- В генераторе маршрутов заводим единый список «публичных» маршрутов: города — только `moskva` и `moskovskaya-oblast`, город×услуга — только для них, кейсы — только при `CASES_PUBLIC`.
- Sitemap строится из публичного списка: примерно 134 → около 60 URL.
- Скрытые города, их город×услуга и кейсы получают `noindex,follow` (страницы остаются доступны по прямой ссылке, вес по внутренним ссылкам не теряется).
- Раздел `/cases` тоже уходит в `noindex` и из sitemap, пока кейсы скрыты.

### 2. Честный lastmod
- Убираем подстановку даты сборки. `lastmod` остаётся только там, где есть реальная дата контента: блог (`publishedAt`).
- Для остальных страниц `lastmod` не выводим — это допустимо и лучше, чем шум.

### 3. Медиа в sitemap
- Добавляем в `urlset` пространства имён `image` и `video`.
- Для каждой страницы услуги и город×услуга подставляем реальные изображения галерей (потоп, пожар) и обложку услуги: `image:loc`, `image:caption` со склонением города.
- Для страниц с видео добавляем `video:video` с `thumbnail_loc`, `title`, `description`, `content_loc` и `duration` — все значения берём из уже существующего медиа-манифеста, так что они гарантированно совпадают с файлами.

### 4. robots.txt
- Явно разрешаем краулинг медиа и статики: `Allow: /media/`, `Allow: /assets/` (сейчас запретов нет, но зафиксируем явно, чтобы будущие правила не перекрыли).
- Заменяем `Disallow: /*?utm|yclid|gclid` на директивы `Clean-param: utm_source&utm_medium&utm_campaign&utm_term&utm_content&yclid&gclid&_openstat /` — Яндекс склеит параметризованные URL с каноническими вместо исключения из обхода.
- Оставляем существующие блоки `Sitemap:`, `Host:` и разрешения для AI-краулеров без изменений.

### 5. Проверки в сборке
- Расширяем `scripts/generate-seo.ts`: после prerender проверяем, что каждый URL из sitemap отдаёт `index,follow` и canonical, совпадающий с `loc`; что ни одна страница с `noindex` в sitemap не попала; что все `image:loc` и `video:content_loc` физически существуют в `dist`.
- Сборка падает при любом расхождении, как и текущие JSON-LD проверки.

## Технические детали

- `src/lib/route-config.ts` — новая функция `getIndexableRoutes()` с фильтрацией по `isVisibleCity` и `CASES_PUBLIC`; `getAllRoutes()` остаётся для prerender (страницы продолжают собираться).
- `src/lib/seoRobots.ts` (или существующее место формирования meta robots) — правило `noindex,follow` для скрытых городов, их город×услуга и кейсов; роуты `cities.$citySlug`, `cities.$citySlug.$serviceSlug`, `cases.$slug`, `cases.tsx` читают его.
- `scripts/generate-seo.ts` — сборка sitemap из `getIndexableRoutes()`, блоки `image:`/`video:` из `src/lib/generated/mediaManifest.ts`, `floodGallery.ts`, `fireGallery.ts`, `serviceImages.ts`.
- `public/robots.txt` — правки в существующем файле, блоки не пересоздаём.
- Проверка: `npm run build:prod` — prerender 134 маршрутов, sitemap около 60 URL, все верификаторы зелёные.
