# Реальные размеры медиа + усиленные связи JSON-LD

## Проблема

1. `width`/`height` фото и видео и `duration` ролика сейчас записаны в коде руками (`floodGallery.ts`, `fireGallery.ts`). Если файл заменят или пережмут — разметка тихо разойдётся с реальностью, и Яндекс/Google получат неверные данные.
2. У обложки страницы (`primaryImageOfPage`) размеров нет вовсе.
3. Связи в графе неполные: `WebPage` не ссылается на хлебные крошки, Organization и основную услугу; в крошках нет «Главная»; галерея и видео не привязаны к странице как `associatedMedia`. Из-за этого поисковики хуже собирают расширенный сниппет.

## Что сделаем

### 1. Размеры и длительность — из реальных файлов

- Новый скрипт `scripts/media-manifest.ts` читает файлы из `public/media` и обложки услуг из `src/assets`, определяет размеры (WebP/JPEG/PNG — чтением заголовка, без внешних зависимостей) и длительность MP4 (разбор атома `mvhd`).
- Результат пишется в `src/lib/generated/mediaManifest.ts`: путь → `{ width, height, duration?, mime, bytes }`.
- Команда `npm run media:manifest`; файл коммитится, поэтому сборка в CI не зависит от ffmpeg.
- `floodGallery.ts` / `fireGallery.ts` перестают хранить числа: размеры и `duration` (в формате ISO `PT34S`) берутся из манифеста по пути файла.
- `serviceImages.ts` дополняется картой «слаг услуги → исходный файл обложки», чтобы `primaryImageOfPage` получал реальные `width`/`height`.

### 2. Проверка при сборке

`scripts/generate-seo.ts` расширяется: для каждого маршрута сравнивает `width`, `height`, `duration`, `contentUrl` и `thumbnailUrl` из JSON-LD с фактическими файлами в `dist`. Расхождение размеров, отсутствующий постер или устаревшая длительность останавливают сборку с понятным сообщением.

### 3. Связи в графе на страницах услуг и город×услуга

- В хлебные крошки добавляется первый пункт «Главная» (сейчас цепочка начинается со второго уровня).
- `BreadcrumbList` получает стабильный `@id` вида `<url>#breadcrumb`, а `WebPage` — поле `breadcrumb` со ссылкой на него.
- `WebPage` дополняется: `publisher` и `about` → Organization, `mainEntity` → `Service` этой страницы (на страницах города — плюс `LocalBusiness`), `associatedMedia` → `ImageGallery` и `VideoObject`, `datePublished`/`dateModified`.
- `Service` и `LocalBusiness` получают `mainEntityOfPage` → `WebPage`, `image` → обложка услуги.
- `Organization.areaServed` приводится к текущей географии (Москва и Московская область), сейчас там остались южные регионы.
- `WebSite`/`Organization` из корневого маршрута остаются единственным источником этих узлов — на страницах только ссылки по `@id`, без дублей.

### 4. Верификация

`npm run build:prod` (134 маршрута) + выборочная проверка готового HTML: наличие `breadcrumb`, `mainEntity`, `associatedMedia`, совпадение размеров с реальными файлами.

## Технические детали

- Читатель размеров: WebP (VP8/VP8L/VP8X), JPEG (маркеры SOFn), PNG (IHDR) — чистый TypeScript, без новых пакетов.
- Длительность MP4: `mvhd` → `duration / timescale`, округление до целых секунд, формат `PT{n}S`.
- Обложки услуг импортируются через Vite и в проде получают хеш в имени; манифест хранит размеры по исходному пути `src/assets/...`, а сопоставление в разметке делается по слагу услуги.
- Ничего не меняется в верстке и текстах — правки только в слое данных, JSON-LD и скриптах сборки.
